# 任务 9：延迟、吞吐和稳定性脚本

完成日期：2026-11-18。正式 8 小时运行已经结束。

## 做了什么

用 1080p 夹具的第一帧测量单帧和 8 帧批量。每组 100 次请求，先各预热 1 次。服务使用 ONNX Runtime CPU、输入边长 640。没有 NVIDIA GPU，显存记 0。

稳定性脚本每 10 秒提交一次同一帧。30 秒冒烟退出码为 0，日志里没有 `unhandled`。冒烟末尾曾经因为剩余时间不足 10 秒而连续补发请求，这个间隔判断已经改成最多睡到截止时间。正式 8 小时运行使用改正后的脚本。

## 文件

| 路径 | 作用 |
| --- | --- |
| `benchmark/latency.py` | 延迟和吞吐 |
| `benchmark/soak.py` | 每 10 秒一帧，写入 `soak.jsonl` |
| `artifacts/reports/latency.json` | 100 次测量结果 |

## 100 次测量

输入是 `ten-second-1080p.mp4` 的第一帧，1920×1080。错误率 0。

| 指标 | 数值 |
| --- | --- |
| 端到端 P50 | 107.13 ms |
| 端到端 P95 | 140.5512 ms |
| 端到端 P99 | 627.4662 ms |
| 服务内部 P95 | 107.1845 ms |
| 单帧吞吐 | 8.1195 帧/秒 |
| 8 帧批量吞吐 | 19.7499 帧/秒 |
| 批量 / 单帧 | 2.4324 |
| 单帧 P95 ≤ 300 ms | 通过 |
| 批量吞吐 ≥ 2 倍 | 通过。6 组 30 次的最低比值是 2.409 |

P99 有一次单帧尖峰。P95 是 140.5512 ms。6 组 30 次里，单帧最快达到 8.947 帧/秒，那一组比值是 2.805。复用连接和每次新开连接都过 2 倍。

队列等待 P95 记的是客户端耗时减去服务内部耗时，包含 JPEG 的 HTTP 传输，不只是排队。这次是 65.8223 ms。进程结束时读到的服务内存是 4,591,616 字节。
